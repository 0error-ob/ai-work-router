# 给你的任务分级

还在用同一个模型跑所有步骤？

有些任务最强的模型反而帮倒忙。

复制下面这段 prompt，贴到对话框，把你的任务填进去，根据结果再做决策：

---

分析一个 AI 工作任务，生成一份普通用户也能看懂的 AI 工作分配建议。

你的目标不是推荐"单一最佳模型"，而是判断：

- 哪些步骤值得用强模型认真想
- 哪些步骤可以交给便宜/快速模型执行
- 哪些步骤应该用工具、测试、表格或规则来检查
- 什么时候需要升级到强模型
- 什么时候应该停止自动化，交给人判断

## 可选上下文

- 成本敏感度：
- 失败成本：
- 可用验证方式：
- 可用工具：
- 上下文大小：
- 是否涉及代码 / 数据 / 文件 / 外部网页：
- 当前痛点：

## 内部分析要求

先在内部完成以下分析，不要逐项输出专业术语：

- 任务结构：验证难度、任务长度、歧义程度、上下文依赖、输出约束、失败成本、可回滚性、成本敏感度
- 工作流拆解：理解任务 → 规划 → 搜索/收集信息 → 执行 → 检查 → 修复 → 交付
- 哪些步骤需要强推理，哪些步骤可以廉价执行，哪些步骤应该用确定性检查
- 升级触发条件和停止条件

## 输出要求

只输出一份简洁的 **AI Work Routing**。

不要输出完整分析报告。
不要堆专业术语。
不要使用具体模型名。
不要说"最佳模型"。
每一步都要让用户知道：下一步做什么、用什么类型的模型/工具、为什么。

## 输出格式

# AI Work Routing

## 一句话策略

用 1 句话说明这个任务应该怎么分配 AI 工作。

## 建议流程

按步骤输出。每一步使用这个格式：

### 1. [步骤名称]

**做什么：**
一句话说明这一阶段要完成什么。

**用什么：**
从下面选择一种或多种，但要用自然语言解释：

- 强模型认真规划
- 便宜/快速模型执行
- 长上下文模型阅读大量材料
- 结构化输出模型整理成表格/JSON/清单
- 工具/测试/规则检查
- 人工判断

**为什么：**
一句话说明为什么这样分配。

## 检查点

列出这个任务最应该检查的 3–5 个点。
优先使用工具、表格、测试、规则、计算，而不是让另一个 LLM 凭感觉判断。

## 什么时候升级

列出具体升级条件。
例如：信息冲突、连续失败 2 次、预算超出、测试失败、需求变模糊、风险变高。

## 什么时候停止自动化

列出哪些情况必须人工判断。
例如：涉及高风险决策、真实付款、法律/签证/医疗/财务风险、无法验证的信息、用户偏好不清楚。

## 最终交付物

说明最后应该输出什么形式，让用户可以直接使用。

## 举个例子

任务：照着写好的步骤，改一小段代码，然后跑测试。

| 步骤 | 怎么处理 |
|---|---|
| 想好怎么改 | 计划已经有了，跳过 |
| 动手写代码 | 用便宜点的模型 |
| 检查对不对 | 跑测试 / 查类型 |
| 修 bug | 最多用便宜模型重试一次 |
| 彻底卡住 | 试两次还错，就换最强的模型 |

## 整体的几个环节

接任务 → 理思路 → 查资料 → 动手 → 检查 → 修 → 交差
