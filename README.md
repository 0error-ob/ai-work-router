# 给你的任务分级

还在用同一个模型跑所有步骤？

更好的做法是分步看：这一步是要最强的模型来死磕，还是便宜点的跑就行？要不要先验证一下？什么时候该停手？

有些任务最强的模型反而帮倒忙。

复制下面这段 prompt，贴到对话框，把你的任务填进去。

---

分析一个 AI 工作任务，生成可执行的工作流路由策略。

你的目标不是推荐"单一最佳模型"，而是判断：

- 哪些阶段值得使用强推理
- 哪些阶段可以使用廉价执行
- 哪些阶段应优先使用确定性验证器
- 什么时候需要升级、停止或人工审核
- 这个任务是否适合自动化

**任务：**

[在此粘贴任务描述]

**可选上下文：** 成本敏感度 / 失败成本 / 可用验证方式 / 可用工具 / 上下文大小 / 是否涉及代码或数据

**先内部完成以下分析（不要输出）：**

- 任务结构画像：oracle 强度 / 视野长度 / 歧义程度 / 上下文依赖 / 输出约束 / 失败成本 / 可回滚性 / 成本敏感度
- 工作流拆解：intake / plan / search / execute / verify / repair / package — 每阶段的目标、推荐路由、reasoning 程度
- 升级触发条件、停止 / 不可自动化条件

**然后只输出 Quick Routing：**

- Intake: [模型类] · [reasoning 程度] · [一句话做什么]
- Plan: ...
- Search / Context: ...
- Execute: ...
- Verify: ...
- Repair: ...
- Package: ...

每行尽量简短。模型类：强推理 · 廉价执行 · 可编程模型 · 长上下文 · 结构化输出稳定型 · 确定性验证器 · 人工审核。不要使用具体模型名。能用确定性验证器时不要用 LLM 判断。能拆成 plan / execute / verify 时不要交给单一模型。

## 举个例子

任务：照着写好的步骤，改一小段代码，然后跑测试。

| 步骤 | 怎么处理 |
|---|---|
| 想好怎么改 | 计划已经有了，跳过 |
| 动手写代码 | 用便宜点的模型 |
| 检查对不对 | 跑测试 / 查类型 |
| 修 bug | 最多用便宜模型重试一次 |
| 彻底卡住 | 试两次还错，就换最强的模型 |

## 整体的几个环节

接任务 → 理思路 → 查资料 → 动手 → 检查 → 修 → 交差
