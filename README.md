# 给你的任务分级

还在傻傻用一个模型跑所有步骤？

聪明的做法是分步看：这一步是要最聪明的模型来死磕，还是便宜点的跑跑就行？要不要先验证一下？什么时候该停手？

有些任务，最聪明的模型反而帮倒忙。

复制下面这段 prompt，贴到对话框，把你的任务填进去。

---

分析这个 AI 工作任务，给出可执行的工作流路由建议。

**任务：**

[在此粘贴任务描述]

**可选上下文：** 成本敏感度 / 失败成本 / 可用验证方式 / 可用工具 / 上下文大小

**输出：** 用 3–7 行给出执行建议，格式如下：

- Intake:
- Plan:
- Search / Context:
- Execute:
- Verify:
- Repair:
- Package:

每行说明使用什么模型类、reasoning 程度、具体做什么。模型类：强推理 · 廉价执行 · 可编程模型 · 长上下文 · 结构化输出稳定型 · 确定性验证器 · 人工审核。不要使用具体模型名。能用确定性验证器时不要用 LLM 判断。

## 举个例子

任务：照着写好的步骤，改一小段代码，然后跑测试。

| 步骤 | 怎么处理 |
|---|---|
| 想好怎么改 | 计划已经有了，跳过 |
| 动手写代码 | 用便宜点的模型 |
| 检查对不对 | 跑测试 / 查类型 |
| 修 bug | 最多用便宜模型重试一次 |
| 彻底卡住 | 试两次还错，就换最强的模型 |

## 整体的几个环节

接任务 → 理思路 → 查资料 → 动手 → 检查 → 修 → 交差
