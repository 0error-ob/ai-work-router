# 给你的任务分级

还在用同一个模型跑所有步骤？

有些任务最强的模型反而帮倒忙。

复制下面这段 prompt，贴到对话框，把你的任务填进去，根据结果再做决策：

---

```
分析一个 AI 工作任务，生成一份普通用户也能照着做的 AI 工作分配建议。

你的目标不是推荐"单一最佳模型"，而是告诉用户：

- 哪些步骤需要认真规划
- 哪些步骤可以交给便宜/快速模型做
- 哪些步骤应该用工具、表格、测试或规则检查
- 什么时候要升级到强模型
- 什么时候必须停止自动化，交给人判断

## 任务

[在此粘贴任务描述]

## 可选上下文

- 成本敏感度：
- 失败成本：
- 可用验证方式：
- 可用工具：
- 上下文大小：
- 是否涉及代码 / 数据 / 文件 / 外部网页：
- 当前痛点：

## 内部分析要求

先在内部分析任务结构，但不要输出专业术语。

内部分析包括：

- 任务是否容易验证
- 任务是单步还是多步
- 任务是否模糊
- 是否依赖大量上下文或实时信息
- 错了会不会很贵
- 是否容易回滚
- 哪些步骤能用工具检查
- 哪些步骤需要人类判断

## 输出要求

只输出一份简洁的 **AI Work Routing**。

不要输出内部分析。
不要堆专业术语。
不要使用具体模型名。
不要说"最佳模型"。
不要让用户感觉这是技术报告。
每一步都要让用户知道：做什么、用什么、为什么。

## 输出格式

# AI Work Routing

## 一句话策略

用一句普通人能听懂的话，总结这个任务应该怎么分配给强模型、便宜模型、工具和人。

## 建议流程

按 5–7 个步骤输出。每一步使用这个格式：

### 1. [步骤名称]

**做什么：**
一句话说明这一阶段要完成什么。

**用什么：**
用自然语言说明使用哪类能力。只能从这些里选：

- 强模型认真规划
- 便宜/快速模型执行
- 长上下文模型阅读大量材料
- 结构化输出模型整理成表格/清单
- 工具/表格/测试/规则检查
- 人工判断

**为什么：**
一句话说明为什么这样分配。

## 检查点

列出 3–5 个最重要的检查点。
检查点必须具体、可执行。
优先使用工具、表格、测试、规则、计算，而不是让另一个 AI 凭感觉判断。

## 什么时候升级

列出具体升级条件。
不要写"情况复杂时升级"这种模糊话。
要写成用户能判断的触发条件。

## 什么时候停止自动化

列出哪些情况必须人工判断。
特别关注真实付款、生产环境、法律/签证/医疗/财务、安全、隐私、不可回滚操作、用户偏好不清楚等情况。

## 最终交付物

说明最后应该输出什么，让用户可以直接使用。

## 输出风格

- 像给一个聪明但非技术用户的工作建议
- 少用抽象名词
- 多用动作词
- 每一步尽量短
- 不要超过用户完成任务所需的信息

## 长度限制

除非任务本身非常复杂，否则总输出控制在 700–1000 字以内。
每个步骤的"为什么"最多一句话。
```

## 举个例子

任务：照着写好的步骤，改一小段代码，然后跑测试。

| 步骤 | 怎么处理 |
|---|---|
| 想好怎么改 | 计划已经有了，跳过 |
| 动手写代码 | 用便宜点的模型 |
| 检查对不对 | 跑测试 / 查类型 |
| 修 bug | 最多用便宜模型重试一次 |
| 彻底卡住 | 试两次还错，就换最强的模型 |

## 整体的几个环节

接任务 → 理思路 → 查资料 → 动手 → 检查 → 修 → 交差
