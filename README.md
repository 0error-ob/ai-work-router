# 给你的任务分级

还在傻傻用一个模型跑所有步骤？

聪明的做法是分步看：这一步是要最聪明的模型来死磕，还是便宜点的跑跑就行？要不要先验证一下？什么时候该停手？

有些任务，最聪明的模型反而帮倒忙。

这个 repo 就三个东西：一段话（复制给 LLM）、一个填空模板、几个例子。

## 举个例子

任务：照着写好的步骤，改一小段代码，然后跑测试。

| 步骤 | 怎么处理 |
|---|---|
| 想好怎么改 | 计划已经有了，跳过 |
| 动手写代码 | 用便宜点的模型 |
| 检查对不对 | 跑测试 / 查类型 |
| 修 bug | 最多用便宜模型重试一次 |
| 彻底卡住 | 试两次还错，就换最强的模型 |

## 整体的几个环节

接任务 → 理思路 → 查资料 → 动手 → 检查 → 修 → 交差
