# 给你的任务分级

还在傻傻用一个模型跑所有步骤？

聪明的做法是分步看：这一步是要最聪明的模型来死磕，还是便宜点的跑跑就行？要不要先验证一下？什么时候该停手？

有些任务，最聪明的模型反而帮倒忙。

这个 repo 就三个东西：一段话（复制给 LLM）、一个填空模板、几个例子。

## 怎么用

**直接复制给 ChatGPT**
展开下方，复制 prompt，贴到聊天框，再把你的任务填进去。

<details>
<summary>展开 prompt</summary>

分析任务结构，生成工作流路由策略。不要推荐单一最佳模型。

**任务：**

[在此粘贴你的任务描述]

**可选上下文：** 成本敏感度 / 失败成本 / 可用验证方式 / 可用工具 / 上下文大小

**输出要求：** 生成完整的 AI Work Routing Card，包含任务 · 任务类型 · 任务结构画像（oracle 强度、视野长度、歧义程度、上下文依赖、输出约束、失败成本、可回滚性） · 工作流拆解（intake → plan → search → execute → verify → repair → package） · 各阶段路由策略 · 升级触发条件 · 不可自动化条件 · 说明

使用模型类，不要使用具体模型名：强推理 · 廉价执行 · 可编程模型 · 长上下文 · 结构化输出稳定型 · 确定性验证器 · 人工审核。优先使用确定性验证。升级条件和停止条件要具体。

</details>

**自己填模板**
打开 `templates/ai-work-routing-card.md` 自己填。

**找人帮忙**
把任务发给懂AI工作流和路由的人，让他用这个项目帮你做张卡。

## 举个例子

任务：照着写好的步骤，改一小段代码，然后跑测试。

| 步骤 | 怎么处理 |
|---|---|
| 想好怎么改 | 计划已经有了，跳过 |
| 动手写代码 | 用便宜点的模型 |
| 检查对不对 | 跑测试 / 查类型 |
| 修 bug | 最多用便宜模型重试一次 |
| 彻底卡住 | 试两次还错，就换最强的模型 |

## 整体的几个环节

接任务 → 理思路 → 查资料 → 动手 → 检查 → 修 → 交差
